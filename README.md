# Rodin for Unreal Canvas

This extension adds Rodin mesh generation to Unreal Canvas through Hyper3D's remote MCP. It targets Canvas server 0.21.0 and version 1 of the Canvas plugin API.

## Installation and account

Publish this directory as the root of a Git repository and tag the release `v0.1.4`. In Canvas open **Settings → Extensions → Install → From a git repository**, select the repository and version, then **Allow** the extension. Canvas installs the official MCP Python SDK into a worker environment using `scripts/rodin_requirements.lock`. The first setup needs access to PyPI and Python 3.10+. The Windows UE test installation includes Python 3.11.

Run the **Rodin Sign In** card or, from this directory, `python scripts/rodin_auth.py login`. The first generation can also initiate sign-in. While approval is pending, Canvas displays the device verification code at the top of the window. The browser opens automatically after three seconds. Compare the codes before approving. **Rodin Account Status** reports local session presence, not a remote account or quota check. `python scripts/rodin_auth.py logout` removes this extension's saved session from this PC. For global revocation use the account provider's controls.

Credential storage belongs to this extension on each platform:

| Platform | Session storage and runtime |
|---|---|
| Windows x64 | Current-user DPAPI at `%LOCALAPPDATA%/RodinCanvasMCP/login.dpapi`. Existing sessions retain the same path and encryption. |
| Apple Silicon macOS | Login Keychain, accessed with Apple's Git `git-credential-osxkeychain` helper (Command Line Tools). Allow access when macOS prompts. |
| Linux x64 | An unlocked Secret Service keyring on the user's desktop D-Bus, accessed with `secret-tool` (`libsecret-tools` on Ubuntu). |

The extension holds an interprocess lock during sign-in and refresh. On macOS the lock and asset index use `~/Library/Application Support/RodinCanvasMCP`; on Linux they use `$XDG_STATE_HOME/RodinCanvasMCP` (default `~/.local/state/RodinCanvasMCP`). POSIX secrets are kept only in the system keyring. Use the same desktop account for the editor and sign-in.

## Publisher setup

Serve `publishing/unreal_canvas_extension.json` at **https://hyper3d.ai/oauth_cimd/unreal_canvas_extension.json** with HTTP 200, JSON content type and public HTTPS access. Its `client_id` must equal its public URL exactly. The authorization server must permit that public client to request device code, refresh tokens, and access to `https://api.hyper3d.com/api/mcp`. For staging, set `RODIN_CANVAS_CLIENT_ID` before launching Canvas. A different client ID requires its own session.

## Cards

- Image to 3D: select **Rodin MCP Image to 3D** in Mesh Generator and connect one local reference image. Choose Tier and Mesh mode in the model parameters. Output is GLB.
- Rigging: choose **Rodin MCP Auto-Rig** in Auto-Rig and connect a mesh. Choose a skeleton template. The worker uses a recorded Rodin asset ID or uploads the mesh for rigging.
- BANG: connect a mesh generated by this extension to **Rodin BANG**. The extension indexes its generated GLBs by SHA-256 to recover their Rodin generation IDs. Adjust Strength to set the target number of parts. The output is a parts GLB.
- Generation is billable. Each worker job submits once. A local Stop stops waiting at the next cancellation point; a submitted cloud job may still complete. Progress includes the Rodin job ID.

With the worker dependencies installed and an active Rodin login, run `python publishing/sync_controls.py` before packaging to refresh these controls from the MCP tool schemas.

## Verification scope

The development loader was exercised in an isolated Canvas server; account status ran as an actual worker. The live publisher document, a full user device approval, UI installation from a tagged repository, and cloud generation under the extension's own client are separate release checks.
